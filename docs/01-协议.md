# 升堂协议 v2（六部制）

> 本文是协议正文。它不是流程图说明，而是**可以直接照着执行**的规范：每一态有唯一合法输入、唯一合法输出、唯一负责人。

---

## 一、角色

| 角色 | 数量 | 权责 | 禁止 |
| --- | --- | --- | --- |
| **主公** | 1 | 提需求、拍板、验收 | —— |
| **中堂** | 1 | 拆单、派司、收附议、汇总 | 不得跳过刑部直接汇总；不得替主公裁决 |
| **六司** | 按单设 | 只做清单上自己的项 | 不得越项、不得直接找主公、不得自审 |

六司职掌：

| 司 | 职掌 | 典型交付物 |
| --- | --- | --- |
| 吏部 | 拆解需求、定人定责 | 可勾选的任务表 |
| 户部 | 资源、预算、素材、数据 | 资源清单、成本估算 |
| 礼部 | 文案、呈现、对外表达 | 说明文档、演示稿 |
| 兵部 | 攻坚、技术实现 | 方案对比、可运行代码 |
| **刑部** | **只审不做** | **勘验结论（通过 / 驳回）** |
| 工部 | 组装、打包、交付 | 归档包、成品 |

**按单设司**：每张升堂单必须写明「本单开哪几司」。没有预设档位，一司也能办，六司也行。

---

## 二、状态机

```
待升堂 → 拆单中 → 附议中 → 执行中 → 勘验中 → 汇总中 → 待验收 → 结案
                    ↑                                      │
                    └──────────── 退回（写明改哪几条）──────┘
```

**严格按序，不能跳。** 每一态的负责人与产出：

| 态 | 负责人 | 合法输出 |
| --- | --- | --- |
| 待升堂 | 主公 | 需求：要做什么 / 做到什么算完 / 预算时间禁区 / 不能动的东西 |
| 拆单中 | 中堂 | 升堂单（见 §三） |
| 附议中 | 六司 | `附议` 或 `异议 + 第几条 + 建议改成什么 + 一句话理由` |
| 执行中 | 各司 | 交活单（见 §四） |
| 勘验中 | 刑部 | 勘验结论（见 §五） |
| 汇总中 | 中堂 | 升堂结果（见 §六） |
| 待验收 | 主公 | `定稿` / `退回 + 改哪几条` / `否决 + 一句原因` |
| 结案 | —— | 归档 |

---

## 三、报文：升堂单

拆单时由中堂发出，格式固定：

```
【升堂单】编号：YYYYMMDD-序号
目标：（一句话）
验收标准：（可勾选的，3～5 条）
约束：本单开哪几司 ／ 闸门 token 上限 ／ 时间 ／ 禁区 ／ 须主公批准事项
任务表：
1. [某司] 做什么 → 交付物是什么
2. …
附议：一轮（有异议写改哪条，无异议回「附议」）
```

**拆单自检**

- [ ] 每条任务只有一个负责司
- [ ] 每条都有明确交付物（文件 / 结论 / 数字，不能是「看看」「研究一下」）
- [ ] 任务之间的依赖写清了（谁先谁后）
- [ ] 刑部**没有**被派执行任务
- [ ] 须主公批准的事项单列（花钱、安装、删除、对外发送）
- [ ] 闸门数字写了

---

## 四、报文：交活单

执行完由各司发出：

```
【交活】升堂单编号 / 任务序号
交付物：（文件路径或正文）
证据：（可复核的东西：命令、输出、链接、行号）
结论：（三句话内）
风险 / 未做：（没有就写「无」）
```

**「证据」这一行是硬要求。** 没有证据 = 未完成。不接受「已完成」「已处理」「应该没问题」这类描述。

---

## 五、报文：勘验结论

由刑部发出，**只对单核证，不问过程**：

```
【勘验】升堂单编号
逐条：
1. 通过 / 驳回（依据：对照验收标准第几条）
2. …
结论：全过 / 驳回 N 条
驳回项：第 X 条，缺什么，补什么才算过
```

**刑部约束**

1. 本单不接执行任务
2. 只使用三样输入：升堂单、交活单、证据。**不看执行过程**
3. 只对照升堂单上已写死的验收标准，不自己发明标准
4. 只能「驳」，不能「否决」——最终裁决权在主公
5. 驳回必须写明「缺什么、补什么」，不能只说「不合格」

---

## 六、报文：升堂结果

由中堂汇总，**只给主公看**：

```
【升堂结果】编号：…
目标是否达成：是 / 部分 / 否
交付清单：（逐条勾，附证据位置）
勘验结论：（刑部原文摘要，不得改写）
关键结论：（不超过 10 行）
待主公拍板：（须批准项、分歧、下一步建议）
```

**汇总自检**

- [ ] 每条任务都有交活，或写明未完成原因
- [ ] 勘验结论是刑部原文，中堂不得美化
- [ ] 没有把过程流水账塞给主公
- [ ] 须批准的事项单列，没有偷偷做掉

---

## 七、附议规则

1. 每人只能回两种内容之一：`附议`，或 `异议 + 第几条 + 建议改成什么 + 一句话理由`
2. **禁止**：跑题闲聊、另开新需求、没看清单就开干
3. 有异议 → 中堂改单 → 再开一轮附议，**最多 2 轮**
4. 2 轮仍谈不拢 → 列分歧请主公拍板
5. 全员附议后，中堂发一句「清单已定，开始执行」并 @ 各司

**超时视为附议**只适用于有真人参与的场合。纯 Agent 场景下，**超时视为未表态**，必须补一轮——静默通过是最危险的假共识。

---

## 八、闸门

| 阈值 | 动作 |
| --- | --- |
| 70% | 冻结范围：不许加新任务，只做清单内的 |
| 100% | 停工，请主公决定是否追加 |

**不设阶段比例。** 单张升堂单一个硬上限，写在单上，超了就是超了。

---

## 九、降级声明

如果这一单只有一个 Agent（没法分司），必须：

1. 在升堂单上写明「本单单司执行」
2. 在升堂结果上写明「**本单无独立审核，为主公自审**」

不许冒充独立审核。**假审核比没审核更糟**，因为它让人放松警惕。

---

## 十、默认时限（有真人参与时适用）

| 阶段 | 默认 |
| --- | --- |
| 拆单 | 升堂后 15 分钟内出清单 |
| 附议 | 发出后 30 分钟（超时视为未表态，需补一轮） |
| 单任务执行 | 清单上写明；未写则 24 小时 |
| 勘验 | 全部交活后 30 分钟 |
| 汇总 | 勘验结论后 15 分钟 |

纯 Agent 场景不用分钟制，用**轮次上限**。
